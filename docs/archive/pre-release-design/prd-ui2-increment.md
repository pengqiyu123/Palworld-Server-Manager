## 一、产品目标

本轮修订聚焦老板实机验收提出的 6 点反馈，达成三件核心事：①修掉配置页展开后内容被裁切、无法滚动查看的问题，并顺带统一所有页面的滚动一致性；②把概览页"一键启动中心"下沉进清晰的启动流程（定位服务器→RadminVPN→游戏，三步各带一个启动按钮，共三个），并移除实测用不上的"检查网络端口"步骤；③把"本服存档"升级为"本地存档"，同时检测本机单机存档（Steam）与服务器存档（专用服），让服主能把单机进度一键迁到服里、免去联机重开档；顺带修复数据迁移页组件挤成一坨的响应式布局，并对全部页面做一次空间排布体检优化。

## 二、可行性与约束（据架构师调研，PRD 定需求基线）

- **存档结构一致**：单机（Steam）与专用服（PalServer）玩法数据结构完全一致——都是 `Level.sav` + `Players/<guid>.sav` + `WorldOption.sav`，仅槽目录名（SteamID64 vs `0`）和磁盘根（Steam Palworld vs PalServer）不同。⇒ "本地存档同时检测两套"在数据层可行。
- **双列表可行性（高）**：现有 F4 `resolve_save_games_root` 兜底已会扫 `common/Palworld/.../SaveGames`（单机位置），只是与 server_path 直拼二选一。把这段 Steam 扫描抽成独立命令并列返回即可，拷贝/备份/迁移命令按路径工作不受影响 ⇒ 近乎零风险。
- **配置页滚动根因**：`.cfg-group`（`style.css:425`）带 `overflow:hidden`，展开后被 flex 压扁裁切；上一轮 `:254` 给 `.cfg-group` 加的 `min-height:0` 加剧此问题。
- **迁移页挤坨根因**：`.op-grid/.world-cols` 硬两列 `1fr 1fr` 无最小宽，`.op-field` 又 `min-width:0`，窄屏压成细条；`.char-label` 还 `white-space:nowrap` 截断。

## 三、用户故事（按 6 点各 1 条）

1. **配置页可滚动**：作为服主，我希望配置页展开任意配置组后整页可滚动查看全部内容，以便不被裁切地读完所有设置项、放心改完再开服。
2. **概览启动流程清晰**：作为服主，我希望概览页把"一键启动中心"放进清晰的启动流程里（定位服务器→RadminVPN→游戏，三步各带启动按钮），以便按步骤开服联机，且不再被实测用不上的"检查网络端口"步骤干扰。
3. **本地存档双检测**：作为服主，我希望本地存档页能同时列出我的单机存档（Steam）与服务器存档（专用服），以便挑一个单机档一键迁到服里、省得联机世界重开档。
4. **清楚能做到什么程度**：作为服主，我希望 app 明确告诉我单机与专用服存档结构一致、可整体迁移（Fix Host Save 已具备），以便放心把单机进度迁到服务器存档。
5. **迁移页不挤坨**：作为服主，我希望数据迁移页的组件按栅格自适应排布、宽屏两列窄屏自动折行，以便窄屏下也能看清每项的名称与字段、不再挤成一坨。
6. **全局布局舒适**：作为服主，我希望整体界面空间排布统一规整、各页滚动一致，以便日常使用舒适不别扭。

## 五、UI 设计稿描述（文字稿）

### 5.1 概览页（S1）新流程视觉结构

```
┌─────────────────────────────────────────────────────┐
│ 顶部常驻区（固定，不随流程滚动）                       │
│  · 服务器状态徽标：服名 / 在线人数 / FPS / 进程态       │
│  · 启 / 停 按钮（保留全局启停）                        │
├─────────────────────────────────────────────────────┤
│ 下方「启动流程」区（可滚动，三步卡片）                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐           │
│  │ ①定位服务器 │  │ ②RadminVPN │  │ ③游戏      │           │
│  │ 状态: 已定位│  │ 状态: 已就绪│  │ 状态: —    │           │
│  │ [启动按钮] │  │ [启动按钮] │  │ [启动按钮] │           │
│  └──────────┘  └──────────┘  └──────────┘           │
│  → 三步各带一个启动按钮（共三个），标注就绪态           │
│  → 已移除「检查网络端口」步骤（原 S1 流程项）          │
└─────────────────────────────────────────────────────┘
```

- 顶部常驻：状态徽标 + 全局启停，信息密度高、不随流程变化。
- 下方流程：三张步骤卡，卡内显示该步就绪态 + 一个启动按钮；三步串联即"开服联机"路径。
- 不再有"检查网络端口"独立步骤（实测与同学联机未做端口检查即成功）。

### 5.2 本地存档页（S7）双区块布局（原「本服存档」更名）

```
┌─────────────────────────────────────────────────────┐
│ 本地存档（标题，Sidebar / router / View 三处同步更名） │
├──────────────────────────────┬──────────────────────┤
│ 区块 A：本地单机存档（Steam）   │ 区块 B：服务器存档（专用服）│
│  · discover_local_worlds 扫   │  · server_path 专用服    │
│    C:/D:/E:…SaveGames         │    存档直列               │
│  · 列表：世界名 / 槽 / SteamID64│  · 列表：世界名 / 槽 / 0    │
│    / GUID / 修改时间           │    / GUID / 修改时间      │
│  · [迁移到服务器] 按钮         │  · [备份] 按钮            │
└──────────────────────────────┴──────────────────────┘
```

- 两个区块并列（宽屏左右、窄屏上下），各自列出 world；单机档提供"迁移到服务器"入口（接 `save_edit` 整包迁移 / Fix Host Save）。
- **命名三处同步（关键）**：①导航 Sidebar 文案「本服存档」→「本地存档」；②路由 router（path 与 name，如 `/local-saves` / `LocalSaves`）；③视图 `SaveManagementView` 内标题与提示文案。三处必须一致，避免 404 / 歧义。

### 5.3 数据迁移页（S8）响应式栅格

```
宽屏（≥约 720px）：
┌──────────────┐ ┌──────────────┐
│ 源档选择(op)  │ │ 目标服档(world)│
│ 字段1  字段2  │ │ 字段1  字段2  │
└──────────────┘ └──────────────┘
窄屏（<720px，自动折行）：
┌──────────────┐
│ 源档选择       │
└──────────────┘
┌──────────────┐
│ 目标服档       │
└──────────────┘
```

- 栅格：`repeat(auto-fit, minmax(220px, 1fr))`，宽屏两列、窄屏自动折一列。
- 修复：移除 `.op-field { min-width:0 }` 压扁、解除 `.char-label { white-space:nowrap }` 截断，字段名与值均清晰可读。

## 六、待确认问题（本轮仍存疑、未拍板）

1. **Oodle 压缩存档是否本轮 UI 预检测红字引导？** PRD 内为 P2 待定项 R7。是否升级为 P0/P1 并红字引导，待老板定；默认保持 P2 待定 / 可选。
2. **Fix Host Save 手动 GUID 互换是否本轮简化？** 默认**不在本轮范围**——迁移页只做"选源单机档 → 选目标服档 → 执行（`save_edit` 整包迁移 / Fix Host Save）"，手动 GUID 互换沿用现有能力，不在 UI 暴露简化版。
3. **概览「三启动按钮」中「游戏」按钮职责？** 是启动本地 Steam 帕鲁客户端（`steam://rungameid/1623730`）还是仅复用 S3 连法说明卡？「RadminVPN」按钮是仅检测就绪还是一键拉起 Radmin 客户端？待老板定（影响 R2 按钮行为）。
4. **单机存档扫描盘符范围？** 老板已拍板扫常见 Steam 库（C/D/E）无需手动指定；若 Steam 装在 F 盘等其他盘，本轮是否覆盖？建议本轮仅覆盖 C/D/E 常见盘，其他盘留 P2。
